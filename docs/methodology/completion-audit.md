## Architecture and measurement boundaries

The numerical simulator lives in [hill.py](../../src/gradientclimb/simulation/hill.py), original learners in [algorithms](../../src/gradientclimb/algorithms), native orchestration in [control](../../src/gradientclimb/control), pixels/readers in [perception](../../src/gradientclimb/perception), and schemas/recording in [experiments](../../src/gradientclimb/experiments). Python/NumPy/PyTorch/Gymnasium, DuckDB/Parquet, FastAPI and a local JavaScript dashboard comprise the implemented path. The [architecture ADR](../decisions/ADR-002-learning-architecture.md) explains alternatives and adoption evidence.

The real bridge exports 49 values plus 49 masks per frame and four-frame history. The linear screen actor selects eight current features plus their masks and biases, 34 parameters total; it does not consume every logged history vector. The restricted student instead has 64 inputs from four frames of the selected eight values/eight masks and two 64-unit layers; it is untrained. Its analytic surrogate silhouette projection is not a pixel-accuracy result. No learned recurrent/dynamics context is adopted.

Pose/terrain availability is not coordinate accuracy. The 38-frame feature check found 38 valid axes but only 15 wheel-supported frames and 18 three-span lookahead measurements. Camera compensation is invalid. The 129-frame independent HUD trajectory had 129 available reads, only four independently selected manual labels checked, 4/4 exact. The 203 result check is source-disjoint but nonblinded post-OCR and one unique image, despite two capture records. Construction 313/229 values are not held-out tests of the final result bank. Unknown scores remain null. [F-002](../../research/findings/F-002-native-observation-and-control.md) and [scoring-readers.md](../operations/scoring-readers.md) preserve exact limitations.
